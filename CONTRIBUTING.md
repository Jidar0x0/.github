# Contributing to Jidar

Thank you for helping improve Jidar.

Most Jidar engineering work is currently performed in private repositories by authorized contributors. Access to a repository does not automatically grant permission to disclose its contents, publish derived materials, or share internal implementation details outside the approved team and systems.

## Before Contributing

- Work only within repositories and environments you are authorized to access.
- Follow the repository's current README, architecture documents, issue requirements, and release gates.
- Do not commit credentials, tokens, private keys, customer data, production exports, or other secrets.
- Keep production changes separate from documentation, diagnostics, experiments, and staging work unless the approved change explicitly combines them.
- Treat security controls, billing behavior, production trust, signing, provisioning, and deployment changes as review-sensitive areas.

## Pull Requests

Contributions should normally be submitted through a pull request rather than direct changes to the default branch.

A pull request should clearly state:

- the problem or requirement being addressed;
- the scope of the change;
- tests or validation performed;
- security, privacy, compatibility, migration, or operational impact;
- any follow-up work or known limitations.

Do not describe a change as production-ready unless the repository's required validation and approval gates have been completed.

## Security Findings

Do not open a public issue for a suspected vulnerability. Follow the organization [Security Policy](SECURITY.md).

## Intellectual Property and Confidentiality

Unless a repository explicitly states otherwise, contributions and repository materials are intended for Jidar's authorized development activities. Do not copy confidential implementation details, internal documentation, customer information, proprietary assets, or unpublished product material into external repositories, AI datasets, public examples, or third-party services without authorization.

Third-party code and assets must be used only in accordance with their licenses and attribution requirements.

## Repository-Specific Rules

Repository-specific instructions take precedence where they impose stricter technical, security, release, or review requirements.
